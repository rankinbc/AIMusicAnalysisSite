## Deferred from: code review of story-1.7 (2026-06-15)

- **JS rAF loops do not honour `prefers-reduced-motion`** [components/frontend-spectr-v2/src/features/results/TranceBot.tsx + features/listen/PreviewTools.tsx + routes/_app/listen.$versionId.tsx] — The story 1.7 CSS-only `@media (prefers-reduced-motion: reduce)` blanket freeze covers every animated CSS class but JS-driven 60 fps canvas/visualizer loops keep running. TranceBot's EQ visor is the most prominent regression — it animates on every Results page load regardless of OS setting. Fix: add a `useReducedMotion()` hook that reads `window.matchMedia('(prefers-reduced-motion: reduce)').matches`, gate the rAF loops on it, and fall back to a static snapshot frame. Story 1.8 (Coach Chat UI) owns the TranceBot consumer; bundle the hook addition there.
- **`box-shadow` keyframe animations are paint-bound (not GPU-compositable)** [components/frontend-spectr-v2/src/styles/global.css `pulseGlow`] — On low-end devices or thermally throttled laptops, the AI Coach tab dot's pulse causes paint jank. Future optimisation: rewrite as `opacity` + `transform: scale()` so the compositor handles it without paint. Visual differs slightly; needs design sign-off.
- **JetBrains Mono + Syne lack italic `@font-face` blocks** [components/frontend-spectr-v2/src/styles/global.css] — `font-style: italic` on either font triggers browser-synthesized oblique (sheared regular) rather than designed italic glyphs. Affects rendering of `<em>` inside coach prose or any markdown emphasis. Add italic blocks pointing at the same WOFF2 file with a `font-style: italic` descriptor once italic-axis support is confirmed in the Fontsource Latin subset.
- **Non-Latin characters silently fall back to `system-ui`** [components/frontend-spectr-v2/src/styles/global.css `@font-face unicode-range`] — Track names containing CJK / Cyrillic / Arabic glyphs render in system-ui while surrounding Latin renders in Syne. Pre-existing behaviour (the prior Google CDN load was Latin-only too); flagged because the audit raised it. Decision: keep Latin-only subset for bundle weight; document the fallback in a font-face comment when the next i18n pass lands.
- **Pre-existing raw `rgba()` literals in `*.module.css` are not covered by `check-css-tokens.mjs`** [components/frontend-spectr-v2/scripts/check-css-tokens.mjs + e.g. src/features/results/SpecialistTile.module.css] — Lint enforces `#rrggbb` hex but ignores `rgba(...)` literals. Pre-existing gap surfaced during story 1.7 review; not introduced by this story. Address as a separate lint-enhancement ticket when commerce surfaces (Epic 2) start adding new colors.
- **`--blue` token has no Pill tone equivalent** [components/frontend-spectr-v2/src/ui/Pill.tsx] — `tokens.css` defines `--blue: #60a5fa` but `PillTone` does not include `'blue'` and `global.css` has no `.pill.blue` rule. Add when Epic 2 commerce surfaces need a blue status pill.
