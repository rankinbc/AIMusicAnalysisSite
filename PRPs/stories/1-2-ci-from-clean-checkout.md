# Story 1.2: CI from Clean Checkout

Status: done

## Story

As the operator,
I want every push verified from a clean checkout with enforcement lints,
so that the relocation and all future work cannot silently break builds or boundaries.

## Acceptance Criteria

1. **Given** a fresh clone, **When** GitHub Actions runs, **Then** BFF `dotnet build` + `dotnet test` pass, frontend `npm ci && npx vite build && npx tsc -b` + lint + vitest pass, and Python `ruff` + `pytest` (including golden fixtures) pass (NFR28).
2. **Given** the routeTree generation quirk, **When** the frontend job runs, **Then** vite build precedes `tsc -b` **And** the `package.json` build script is fixed to the same ordering.
3. **Given** the frozen-v1 components, **When** CI runs, **Then** they are excluded from all gates.
4. **Given** the enforcement lints (AR39), **When** CI runs, **Then** an `anthropic` import outside `llm/gateway.py` fails the build, a raw hex color in a CSS module fails the build, and a price literal outside config fails the build.

### Critical guardrails

1. **Frozen-v1 exclusion is by omission + comment, not by `paths` filters** — path filters on jobs would skip the WHOLE job when only v1 changed; simpler and safer to just never reference v1 components anywhere.
2. **Don't introduce Tailwind/PostCSS/stylelint for the hex lint** — a 30-line node script keeps the dependency surface zero. NO new npm packages for any lint.
3. **Hex cleanup must be color-identical** — map each hex to the token holding that exact value; only mint a new token in `tokens.css` if the value genuinely has no home. Don't "improve" colors; story 1.7 (Phase A) owns token design (UX-DR3).
4. **The anthropic lint allows a path that doesn't exist yet** — `components/worker/app/llm/gateway.py` (story 1.3). Lint by path-suffix match, not file existence.
5. **Self-scan trap**: the enforcement-lint test file itself contains the strings it forbids — build patterns via concatenation (established in `test_frozen_v1_boundary.py`).
6. **`npm ci` requires `package-lock.json`** — confirm it's committed; if missing, generate with `npm install --package-lock-only` and commit (that IS clean-checkout hygiene).
7. **Windows dev box vs ubuntu runner**: watch for CRLF (`.gitattributes` absent — git autocrlf handles it), case-sensitive paths, and `python` vs `python3` (use `python` from setup-python).
8. **Shared install order**: `pip install -e components/shared` BEFORE worker requirements (`aimusic-shared>=0.1.0` resolves from the editable install, not PyPI — it does not exist on PyPI).
9. **No secrets in the workflow** (NFR6): CI needs none — no DB, no Redis, no API keys. If a future step wants one, that's a different story.
10. **Keep the three jobs parallel** (no `needs:`) — fastest signal; nothing depends on another job's artifacts.
