# analysis

**Purpose**: Self-contained Python package containing all 7-phase audio analysis pipeline modules, adapted from the existing AbletonAIAnalysis project. Installed as an editable package so `api` and `worker` can import from it. Exposes a single entry point: `run_pipeline(file_path, reference_path=None, progress_cb=None)` that runs all phases sequentially and returns a structured dict. Phases: (1) universal mix analysis — LUFS/loudness, 7-band frequency balance, stereo health, transient analysis, BPM; (2) genre auto-detection; (3) genre-specific scoring (trance/house/techno/dnb); (4) stem separation + clash detection via Demucs htdemucs_ft; (5) reference track comparison; (6) genre profile gap analysis vs curated reference library; (7) arrangement advisor.

**Inputs**: `data/uploads/` (audio files), `data/reference_library/` (curated pro reference tracks by genre), `data/models/` (cached ML weights)

**Outputs**: `output/analysis_results/` (per-job JSON)

**Pattern**: `analysis.md`

**Stack**: Python 3.11+ — librosa, pyloudnorm, soundfile, torch, demucs, torchopenl3, all-in-one-fix, numpy<2.0

## How to run

```bash
# Install editable from project root
pip install -e components/analysis

# Verify package is importable
python -c "from audio_analysis import run_pipeline; print(run_pipeline('data/uploads/test.wav'))"

# Run tests
pytest components/analysis/tests/
```

## Windows note

Phase 7 (arrangement advisor) uses `all-in-one-fix`, which depends on NATTEN. NATTEN has no Windows wheels. Run phase 7 inside Docker or WSL2 on Windows hosts. Phases 1-6 run natively on Windows.

## stems/ module — per-stem analysis (added 2026-04-26)

When the user uploads individual stems alongside the mix, all stem
logic lives in `audio_analysis.stems`. Phases 4 and 5 call into it
conditionally; the public package surface is small and stable:

```python
from audio_analysis.stems import (
    detect_role,                  # filename + spectral role classification
    propose_mapping,              # auto-mapping for the confirmation UI
    validate_confirmed_mapping,   # server-side guard on confirmed mappings
    analyze,                      # per-stem metrics + clash matrix
    compare,                      # per-stem reference deltas
)
```

Phases 4 and 5 keep their existing output schemas and add
`phase4.stems` / `phase5.per_stem_reference_deltas` only when stems
are present. Three verdict specialists (`stem_balance`,
`stem_stereo_width`, `stem_reference_delta`) run only when stems exist;
two existing specialists (`frequency_collision`, `frequency_balance`)
gracefully use the richer data when available.

## Pre-Demucs runbook (admin / one-off)

Curated reference tracks in `data/reference_library/` are
pre-processed offline so phase 5 can do per-stem reference comparison
without paying Demucs cost per request:

```bash
python -m audio_analysis.reference_library.pre_demucs \
    --library data/reference_library/ \
    --out     data/reference_library/_stems_cache/ \
    [--track <id>]
```

Idempotent — already-cached tracks (cache file newer than source) are
skipped. Without the cache, phase 5 still works but falls back to
full-mix comparison when the user provides stems against a curated
reference. User-uploaded reference stems bypass the cache entirely.
