# SPECTR BFF Architecture

Component: `components/bff/` — generated by BMAD document-project deep scan, 2026-07-22.
Source of truth: `components/bff/src/Spectr.Bff/` (all paths below are repo-relative unless absolute).

## Executive Summary

The BFF is an ASP.NET Core .NET 10 minimal-API gateway and the single backend for the
`frontend-spectr-v2` React SPA. It owns authentication (JWT access + rotating refresh cookie),
songs/versions/uploads CRUD, media streaming (Range-enabled, local-proxy or presigned-302),
analysis job dispatch onto dramatiq Redis queues (tier-routed paid/free lanes), results and
verdict retrieval, the coach conversation relay (SSE over Redis pub/sub), Stripe billing
(checkout, webhook mirror, append-only credit ledger), the anonymous instant-analysis funnel,
version sharing / rooms (Listen V3), social surfaces (profiles/follow/feed/notifications),
GDPR export/delete, and an X-Admin-Key operator surface. It never runs analysis itself — the
Python dramatiq worker does; the BFF writes job rows + Redis messages and reads Postgres results.
Roughly 198 mapped routes across 36 endpoint files, ~49 service classes, 3 projects + 1 test
project (~64 test classes). A legacy FastAPI service (`components/api/`) still exists but is
being phased out; nothing here depends on it.

## Architecture Pattern

Three projects plus tests:

- `src/Spectr.Bff/` — the host. Composition root is `Program.cs` (683 lines: config fail-fast,
  DI, JWT pipeline, CORS, middleware order, route group mapping, `/healthz`, `/metrics`,
  boot migrator). Exposes `public partial class Program` for `WebApplicationFactory<Program>`.
- `src/Spectr.Data/` — EF Core `AppDbContext` + entities + migrations (snake_case mapping).
  Canonical schema owner; the Python worker mirrors these models in `aimusic_shared`.
- `src/Spectr.Domain/` — thin shared-domain project (no packages).

Conventions inside `Spectr.Bff`:

- **Endpoint groups**: one static class per resource in `Endpoints/*Endpoints.cs` (36 files),
  each exposing `Map<X>Endpoints(this IEndpointRouteBuilder)` that creates a `MapGroup` and
  registers handlers as private static methods. All groups except crawler shells/webhooks mount
  under the `/api` group created in `Program.cs`.
- **DTOs**: sealed C# records in `src/Spectr.Bff/DTOs/*.cs` (e.g. `JobDtos.cs`, `BillingDtos.cs`,
  `VersionDtos.cs`, `CoachConversationDtos.cs`). Some endpoint-local request records live inline
  in the endpoint file (e.g. `UploadEndpoints.InitRequest`).
- **Services layer**: `src/Spectr.Bff/Services/` (49 files) — interface-first seams
  (`IFileStorage`, `IJobQueue`, `IMultipartObjectStore`, `IRateLimiter`, `IEmailSender`,
  `IStripeCheckoutClient`/`SubscriptionClient`/`RefundClient`, `INotificationSink`,
  `IPresetGenerator`, `ITokenResolver`) with concrete implementations registered in `Program.cs`.
  Auth-specific helpers live in `src/Spectr.Bff/Auth/` (JwtTokenService, RefreshTokenService,
  AuthTokenService, PasswordHasher, AdminAuth, ClaimsPrincipalExtensions, HandleSeeder).
- **Options**: `src/Spectr.Bff/Options/` bound + `ValidateOnStart()` (StripeOptions, ResendOptions,
  WorkerOptions, CoachCapsOptions, AnonOptions, S3StorageOptions, RetentionOptions, LifecycleOptions,
  PricingDisplayOptions).

Middleware order (Program.cs): ForwardedHeaders (config-gated, prod-Caddy-only) → unconditional
exception handler (shared envelope, trace id, never a stack frame) → correlation-id enrichment
(jobId/analysisId route values pushed into Serilog LogContext + Sentry tag) →
SerilogRequestLogging → HttpMetrics → CORS → Authentication → Authorization →
`UseAnonIdentity()` (mints/verifies the `spectr_anon` cookie) → routes.

## Auth Model

- **Access token**: HMAC-SHA256 JWT, 15-minute TTL (`Jwt:AccessTokenMinutes`), issuer
  `spectr.bff` / audience `spectr.web`. Carries a `tver` (token-version) claim; on every request
  `OnTokenValidated` compares it against `users.token_version` (60 s IMemoryCache per user,
  fail-OPEN on DB blips) and also rejects banned accounts. Password reset / account deletion /
  ban bump the version, killing live tokens within ≤60 s. (`Program.cs` lines 105–206,
  `Auth/JwtTokenService.cs`.)
- **Refresh token**: opaque token in httpOnly cookie `spectr_refresh`, 30-day TTL, rotated on
  every `POST /api/auth/refresh`; row stored server-side and revoked at logout
  (`Auth/RefreshTokenService.cs`, `Endpoints/AuthEndpoints.cs`). Access tokens are never stored
  in localStorage — module state on the frontend only.
- **Query-param JWT (`?t=`)**: `<audio>`/`<img>` cannot set headers, so `OnMessageReceived`
  accepts the access JWT via `?t=` on exactly two path shapes: `/api/versions/{id}/audio` and
  `/api/jobs/{id}/images/{kind}`. Same validation pipeline; deliberately tight carve-out
  (review fix P24 — no substring matching).
- **Opaque resource tokens (`?token=`)**: version-share and room-session tokens resolve through
  `Services/ResourceTokenAuth.cs` + `ITokenResolver` implementations (`ShareTokenResolver`,
  `SessionTokenResolver`) — explicitly NOT the JWT `?t=` hook. Used by `/api/v/{token}` and
  `/api/sessions/{id}` anon access.
- **Anon device cookie `spectr_device`**: HMAC-signed device identity minted by
  `Services/DeviceService.cs` on the first `POST /api/anon/analyses`. Scopes the anon funnel;
  registration with the cookie present claims the device server-side and re-parents its
  jobs/analyses/conversations (AuthEndpoints.Register, story 4.5), then clears the cookie.
- **Durable anon cookie `spectr_anon`**: separate stateless HMAC identity (key `Anon:SigningKey`,
  must differ from `Jwt:Key` — boot-enforced) minted by `AnonIdentityMiddleware` for
  unauthenticated visitors; used for anon attribution in feedback/bookmarks/rooms.
- **Dev login**: `POST /api/auth/dev-login` — Development-environment-only (404 otherwise);
  logs in a pre-registered user by email without a password. Consumed by
  `frontend-spectr-v2/src/auth/AuthContext.tsx`.
- **Email tokens**: `Auth/AuthTokenService.cs` issues verify-email / reset-password tokens
  (story 4.3); `Auth:DevAutoVerify=true` (Development only) stamps `EmailVerifiedAt` at register.
- **Admin**: `X-Admin-Key` header checked by `Auth/AdminAuth.cs`; surface 404s until
  `Admin:ApiKey` is configured (min 32 chars outside Development).

## Core Services (src/Spectr.Bff/Services/)

- **IFileStorage** (`IFileStorage.cs`) — `LocalDiskFileStorage` resolves keys under
  `Storage:LocalRoot` (repo `data/`; note the four-`../` gotcha). Registered as the default;
  R2 is served via the S3 path below rather than a second IFileStorage impl.
- **IMultipartObjectStore / S3ObjectStore** (`IMultipartObjectStore.cs`, `S3StorageOptions.cs`) —
  presigned multipart upload (init/part-URLs/complete/abort), single-PUT presign, presigned GET.
  `IsConfigured=false` (no `Storage:S3:ServiceUrl`) makes `/api/uploads/*` answer
  501 `presigned_unavailable`; the frontend falls back to the legacy proxy upload.
- **IJobQueue / DramatiqJobQueue** (`IJobQueue.cs`) — dramatiq wire format: payload JSON in HASH
  `dramatiq:<queue>.msgs` keyed by `redis_message_id`, id RPUSHed onto LIST `dramatiq:<queue>`,
  both inside MULTI/EXEC. `options.redis_message_id` MUST match the list entry or the Python
  broker KeyErrors on ack. `EnqueueDelayedAsync` writes `<queue>.DQ` with `options.eta`.
  Actor/queue name constants: `DramatiqTasks.cs` (12 actors), `DramatiqQueues.cs`
  (coach, analysis-paid, analysis-free, maintenance; `default` is compile-compat only — no
  live enqueue targets it, enforced by `DeployTopologyTests`/worker tests).
- **MediaDelivery** (`MediaDelivery.cs`) — shared serve-tail for every media endpoint:
  local-first proxy stream (`Results.File` with `enableRangeProcessing: true`), else 302 to a
  short-lived presigned S3 GET with `Cache-Control: no-store` (never 301). Result images get
  `immutable` caching on the local branch. Auth/ownership always happens in the endpoint first.
- **EntitlementService** (`EntitlementService.cs`) — the single tier resolver (pro if
  subscription active/past_due; credits if balance ≥ 1; else free). Per-user snapshot cached
  60 s (`ent:{userId}`); feature flags cached 60 s (`feature_flags_global`) via `GetFlagsAsync`.
  invalid_file failures are excluded from the monthly free/pro meter at read time (AR16).
  Never injected into job-status/results read paths (results-forever, AR15).
- **CoachCapService** (`CoachCapService.cs`) — COUNT half of the two-guard model: free =
  per-analysis cap (`coach_free_followups` flag, default 3), pro = pooled monthly
  (`coach_pro_monthly` flag, default 300, resets on the YYYY-MM boundary), credits = unlimited.
  Refused turns are read-side excluded. The worker's LLM gateway gates SPEND independently.
- **CreditLedgerService** (`CreditLedgerService.cs`) — the ONLY writer to `credit_ledger`
  (append-only; purchase on webhook, spend at dispatch, lazy reversal on invalid_file via
  `GET /api/jobs/{id}` with idempotency key `reversal:<jobId>`).
- **SubscriptionMirrorService** — the ONLY writer to `subscriptions` (mirrors Stripe webhooks).
- **SpecialistCatalog** (`SpecialistCatalog.cs`) — canonical list of 26 specialist slugs; must
  stay 1:1 with the worker's `verdict_lib/prompt_loader.SLUG_TO_FILENAME`.
- **StaleJobReaper** (`StaleJobReaper.cs`, hosted) — 60 s sweep failing orphaned jobs:
  processing > `Worker:StaleJobMinutes` (30), pending > `PendingGraceMinutes` (240), and a fast
  tier — pending > `PendingNoWorkerGraceMinutes` (dev 5 min) when the dramatiq heartbeat
  (`WorkerHeartbeat.cs`, `dramatiq:__heartbeats__` ZSET) is stale. Sets
  `error_code=worker_unavailable` (deliberately not `invalid_file` so no refund fires).
- **IRateLimiter / RedisRateLimiter** (`IRateLimiter.cs`) — atomic Lua sliding-window over TWO
  arms (actor + IP); either arm over limit denies → 429 `rate_limited`. Fail-OPEN on Redis
  errors everywhere it is used. Global kill switch `RateLimits:Enabled=false` (Development).
  IPv6 is bucketed to /64 (`VersionEndpoints.NormalizeIpForLimiting`).
- **RoomBus** (`RoomBus.cs`) — Redis WAL + pub/sub engine for room sessions (SSE fan-out).
- **CoachChatService** (`CoachChatService.cs`) — wraps the `claude` CLI subprocess for the
  legacy coach path; the live path goes through the `coach_reply` worker actor.
- **Email**: `QueueEmailSender` (renders via `EmailTemplates.cs`, checks suppression, enqueues
  `send_email` on `maintenance`), `LifecycleEmailScheduler` (analysis-complete poller),
  `RetentionSweepScheduler` (nightly `sweep_retention`), `DisposableEmailService` (10.6 abuse).
- **Background hosted services**: BillingReconciliationService (nightly read-only drift check),
  StaleJobReaper, RetentionSweepScheduler, LifecycleEmailScheduler. Plus `BootMigrator.cs`
  (migrations at boot under advisory lock when `Migrations:ApplyAtBoot=true`).
- **Other seams**: `AccessService` (version share gate resolution), `HonestMathService` (usage
  page math), `ReferenceProfileAggregator` (fingerprint-cached reference-set aggregate),
  `DemoSeeder` (first-run demo report), `MentionParser`, `TableNotificationSink`, `AppUrls`,
  `UlidGen`, `AnonReportProjection`/`ShareReportProjection` (reduced public projections).

## Job Dispatch and Tier Routing

`VersionEndpoints.DispatchAnalysisAsync` (`Endpoints/VersionEndpoints.cs` lines 1050–1358) is the
single authoritative dispatch path used by `POST /api/versions`, `POST /api/uploads/complete`,
`POST /api/versions/{id}/analyze`, `/stems/confirm`, and `POST /api/jobs/{id}/retry`. Order:

1. IDOR guard on caller-supplied referenceId.
2. Entitlement check (`entitlement_exhausted` 409 when `AnalysesRemaining == 0`; skipped for
   free retries).
3. Cross-account abuse arms (free tier only, fail-open): disposable-email reduced cap
   (`disposable_free_analyses` flag, default 1) and per-IP hourly dispatch ceiling
   (`dispatch_per_ip_hourly` flag, default 10) → 429 `rate_limited`.
4. Second-analysis email-verification gate: unverified free users get exactly one analysis;
   next dispatch → 403 `email_verification_required` (pro/credits exempt; free retries exempt).
5. Row writes by tier: credits → insert job then `CreditLedgerService.SpendAsync` (race →
   job failed `insufficient_credits`, 409); free/pro → job + `usage_events` row in one
   SaveChanges; freeRetry → job row only with `RetryOfJobId` (partial unique index is the
   once-only authority → 409 `retry_already_used`).
6. Enqueue `analyze_audio_job` AFTER commit, tier-routed: pro/credits → `analysis-paid`,
   free/anon → `analysis-free`. Enqueue failure marks the row `dispatch_failed` (or deletes a
   free-retry row) and rethrows.

Secondary actors (`run_triage`, `run_specialist`, `generate_fix_rack`, `rerun_phase`,
`run_reference_analyzer`, `classify_stems`) enqueue on `analysis-paid`; `coach_reply` on
`coach`; housekeeping (`sweep_retention`, `send_email`, `delete_account_data`) on `maintenance`.
Queue depth for all four lanes (+ `.DQ`) is exported as the `spectr_queue_depth` gauge at
`/metrics` scrape time (Program.cs).

## Billing (Endpoints/BillingEndpoints.cs, 1230 lines)

- Checkout: `POST /api/billing/checkout/subscription` and `/checkout/credits` via
  `IStripeCheckoutClient`. Every mutating Stripe call carries a deterministic
  `IdempotencyKey` (`customer:{userId}`, `session:{userId}:{priceId}`) so retries never
  duplicate. Stripe.net 52.x note: per-item billing periods read via
  `stripeSub.Items.Data[0]`, not the subscription root.
- Manage: `GET /billing/me`, `POST /billing/cancel|resubscribe|change-cadence|portal`,
  `GET /billing/credits`, `GET /billing/plans` (anon; display prices from
  `PricingDisplayOptions`, never live Stripe).
- Webhook: `POST /api/billing/stripe/webhook` (signature-verified). Idempotency pattern:
  `INSERT INTO webhook_events ... ON CONFLICT (id) DO NOTHING`, then skip only when
  `processed_at IS NOT NULL` (a row whose first dispatch failed is retried); success stamps
  `processed_at`, failure records `processing_error` and 500s so Stripe redelivers.
  Handles `checkout.session.completed` (mode=payment → credit purchase; mode=subscription →
  mirror), `customer.subscription.created/updated/deleted`, `invoice.paid/payment_failed`.
- Boundaries: `SubscriptionMirrorService` = only subscriptions writer;
  `CreditLedgerService` = only credit_ledger writer; the worker never touches billing tables
  (the BFF's lazy read-path reversal + nightly `BillingReconciliationService` close the loop).
- Boot: keys optional in dev (checkout answers `stripe_not_configured`); `SPECTR_REQUIRE_STRIPE=1`
  makes SecretKey/WebhookSecret/price ids mandatory at startup.

## Error Envelope

`Endpoints/ErrorEnvelope.cs` — `ErrorEnvelope.Build(status, code, message, details = null)` emits
the AR38 shape `{ "error": { "code", "message", "details" } }`. Frontends key off `code` only.
The unconditional exception handler in `Program.cs` emits the same shape as 500 `internal_error`
with `details.traceId`. Representative typed codes (grep `ErrorEnvelope.Build` for the full set):
`rate_limited` (429), `entitlement_exhausted` (409), `insufficient_credits` (409),
`email_verification_required` (403), `coach_cap_reached` (403, details `{used,limit,scope}`),
`coach_offline` (503), `anon_active_analysis` (409), `retry_not_eligible` / `retry_already_used`
(409), `presigned_unavailable` (501), `storage_unreachable` (503), `upload_not_found` (502),
`entitlements_unavailable` (503), `invalid_file` (400), `account_banned` (403), `invalid_token`
(400), `not_host` / `not_owner` / `*_forbidden` (403), `session_ended` (409),
`stripe_not_configured`. Plain `Results.BadRequest(new { error = "..." })` still appears in some
older validation branches — the envelope is the convention for machine-actionable codes.

## Configuration

- `appsettings.json` — safe defaults, NO signing keys: Postgres/Redis conn strings, Jwt
  issuer/audience/TTLs, `Storage:LocalRoot: "../../../../data"` (resolves from the project dir to
  repo `data/`), Worker reaper knobs, CoachCaps, Stripe placeholders, PricingDisplay.
- `appsettings.Development.json` — dev-only signing keys (`Jwt:Key`, `Anon:SigningKey`),
  `RateLimits:Enabled=false`, `Auth:DevAutoVerify=true`, `Worker:PendingNoWorkerGraceMinutes=5`.
  Excluded from publish (`CopyToPublishDirectory=Never`).
- Boot fail-fast (`Program.cs RequireSigningKey`): outside Development the BFF refuses to start
  on missing/short (<32 bytes)/placeholder/publicly-committed dev keys; `Jwt:Key` must differ
  from `Anon:SigningKey`; `App:FrontendOrigin` required outside Development (email deep links +
  the single CORS origin, credentials allowed — never `*`).
- Opt-in env gates: `SPECTR_REQUIRE_STRIPE=1`, `SPECTR_REQUIRE_EMAIL=1` (Resend),
  `Migrations:ApplyAtBoot=true`, `ForwardedHeaders:Enabled=true` (prod Caddy only),
  `Sentry:Dsn`, `Admin:ApiKey`, `Storage:S3:*` (presigned uploads), `Resend:*`.
- Kestrel body limit 250 MB; multipart form limit 5 GB (bulk stem staging).
- Run: `cd components/bff/src/Spectr.Bff && dotnet run` → `http://localhost:5000`. Windows
  gotcha: stop a running BFF before `dotnet build` (exe file lock).

## Testing

`components/bff/tests/Spectr.Bff.Tests/` — single xunit project, 68 .cs files: ~64 test classes
plus shared support (`TestSupport.cs`, `TestEnv.cs`, `StripeTestUtilities.cs`) and

## Experience-Relevant Behaviors (what the UI actually feels)

- **Rate limits**: auth endpoints, uploads (10/min), dispatch (10/h/IP), profile reads, follows,
  feedback, account ops → 429 `rate_limited`; all fail-open on Redis trouble; off in Development.
- **Caps surfaced to the UI**: `GET /api/me/entitlements` returns `EntitlementsDto`
  (tier, analysesRemaining/limit/used, resetsAt, stems/als/fullVerdicts flags, historyDepth,
  nested `CoachCapsDto {used, limit, capReached, scope: analysis|month|unlimited, resetsAt}`)
  — drives upgrade sheets and FR15 chip grammar. Coach cap breach → 403 `coach_cap_reached`
  with the same numbers in `details`.
- **202 + poll**: `POST /versions/{id}/analyze`, `/stems/classify`, `/reports/{jobId}/fix-rack`,
  `/reports/{jobId}/verdicts/run/{slug}`, `/reports/{jobId}/phases/{p}/rerun`,
  `/references/analyze`, room event posts → `202 Accepted`; clients poll `GET /api/jobs/{id}`
  (TanStack Query) — the SSE `GET /jobs/{id}/stream` exists but the v2 UI polls instead.
- **204-until-ready**: `GET /reports/{jobId}/fix-rack` returns 204 until the worker's
  `generate_fix_rack` preset lands; coach replies arrive as pending assistant rows completed
  via the SSE `GET /coach/{analysisId}/messages/{messageId}/stream`.
- **Email verification gate**: only at dispatch time (second analysis, free tier) — report
  viewing is never gated. Dev auto-verify keeps local flows unblocked.
- **Worker-death honesty**: `GET /api/health/worker` powers the global "worker offline" banner;
  StaleJobReaper turns orphaned spinners into re-runnable failures; free retry
  (`POST /jobs/{id}/retry`) gives one entitlement-free re-run for failed/degraded paid analyses.
- **Results forever**: job status/results reads have no entitlement gate by design (AR15).
