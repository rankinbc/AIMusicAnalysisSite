# Integration Architecture — how the parts communicate

Generated by the BMAD document-project workflow (deep scan, 2026-07-22).

## Topology

```
Browser (React SPA :5174)
   │  REST /api/* + SSE (Vite proxy in dev; credentials: include)
   ▼
BFF (ASP.NET Core :5000) ──────────────► PostgreSQL 16 (EF Core, canonical schema)
   │  dramatiq wire format                     ▲
   │  (Redis HASH+LIST enqueue)                │ SQLAlchemy sync (psycopg2)
   ▼                                           │
Redis 7 ──── consume 4 queues ────► Worker (Python dramatiq)
                                        │ run_pipeline()          │ subprocess
                                        ▼                         ▼
                                  audio_analysis lib        `claude` CLI / Anthropic SDK
                                        │ docker run
                                        ▼
                                  allin1:latest container (structure detection)
```

Shared stores: one Postgres (BFF writes/reads via EF; worker via SQLAlchemy
mirror `aimusic_shared`), one Redis (queues + heartbeats), one file store
(`IFileStorage`: repo `data/` locally, R2 in prod — worker resolves paths
against `STORAGE_LOCAL_ROOT`).

## Integration points

| # | From → To | Type | Contract |
|---|---|---|---|
| 1 | frontend → bff | REST `/api/*` | JSON, JWT bearer access token (module state) + refresh httpOnly cookie; 401 → silent refresh + retry in `fetcher.ts` |
| 2 | frontend → bff | SSE | Coach message stream `GET /api/coach/{id}/messages/{id}/stream`; room streams `GET /api/sessions/{id}/stream` |
| 3 | frontend → bff | media | `GET /api/versions/{id}/audio` Range-enabled; JWT via `?t=` query param (HTMLMediaElement cannot set headers); `crossOrigin="anonymous"` for Web Audio |
| 4 | bff → redis | dramatiq enqueue | `dramatiq:<queue>.msgs` HASH (message_id → JSON) + `dramatiq:<queue>` LIST, written atomically (MULTI/EXEC); `options.redis_message_id` must match |
| 5 | bff → worker (logical) | tier routing | `DispatchAnalysisAsync`: pro/credits → `analysis-paid`, free/anon → `analysis-free`; auxiliary actors on `analysis-paid`; housekeeping on `maintenance`; coach on `coach`; NO `default` queue |
| 6 | worker → postgres | SQLAlchemy sync | 3-phase tx in `analyze_audio_job` (claim → compute without tx → persist); writes `analyses.final_json`, verdicts, rack presets |
| 7 | worker → bff (indirect) | DB + Redis state | job status/progress read by BFF (`GET /api/jobs/{id}`); worker heartbeats ZSET `dramatiq:__heartbeats__` power `GET /api/health/worker` (caveat: orphan fork keeps heartbeat fresh — see STARTUP.md #3) |
| 8 | worker → allin1 | `docker run` per track | deferred `detect_structure_job`; timeout `ALLIN1_TIMEOUT` (1800 s), GPU via `ALLIN1_USE_GPU=1`; merges structure into the SAME analysis row and re-scores phase 7 |
| 9 | worker → Anthropic | `claude` CLI subprocess (dev, `USE_CLAUDE_CLI=1`, Semaphore(1)) / SDK (prod) | specialist verdicts, triage, coach replies, fix-rack arbiter; `LLM_FAKE=1` = canned; budget gates in `llm/budget.py` |
| 10 | bff → Stripe | REST + webhooks | idempotency keys on all mutations; webhook dedupe table (`INSERT … ON CONFLICT`, processed_at-conditional) |
| 11 | bff → Resend | REST (email) | verification/reset emails; `SPECTR_REQUIRE_EMAIL=0` in dev; `send_email` actor for async sends |
| 12 | bff ↔ storage | IFileStorage | local: direct streaming via MediaDelivery; S3: presigned PUT/GET (`Storage__S3__ServiceUrl` is the switch; 501 `presigned_unavailable` → frontend proxy-upload fallback) |
| 13 | frontend ↔ bff (anon) | device cookie | `spectr_device` HMAC cookie scopes anon analyses; registration claims + re-parents |

## Async result-delivery patterns (what the UI polls)

- Analysis job: `GET /api/jobs/{id}` polled; results at `GET /api/jobs/{id}/results`.
- Arrangement: results poll every 4 s until `arrangement_status` leaves `pending`.
- Fix Rack: `POST /api/reports/{jobId}/fix-rack` 202 → `GET` 204-until-ready,
  poll capped ~150 s with component timeout state.
- Verdicts: list polling (SSE endpoint exists server-side but is unused by the SPA).
- Coach chat: POST message → SSE token stream for the reply.

## Failure-propagation notes

- Worker down: jobs queue unconsumed; BFF `StaleJobReaper` fails `processing`
  jobs after `Worker:StaleJobMinutes` (30); shell worker-health notice appears;
  queued `pending` messages survive restart (Redis AOF, NFR16).
- LLM budget exceeded: `analyses.degradation_notice` set → coach returns
  `coach_offline` (bypassed when `USE_CLAUDE_CLI=1`).
- Storage misconfig (native run with compose-only `/data`): every job fails
  file resolution — worker boot log `storage_root=` is the tell (STARTUP.md #7).
- Feature flags (`feature_flags` table) are read by BOTH services on a 60 s
  cache, fail-open — live knobs without redeploys.
