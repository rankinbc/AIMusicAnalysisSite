# Project Overview — SPECTR (AI Music Analyzer)

Generated by the BMAD document-project workflow (deep scan, 2026-07-22).
Master navigation: `index.md`.

## What it is

SPECTR is a web app for music producers. Users upload a track (MP3/FLAC/WAV,
≤250 MB) and receive a graded, measured mix report from a multi-phase audio
analysis pipeline (loudness, frequency balance, stereo, transients, genre DNA,
stems, reference deltas, arrangement), plus on-demand AI specialist verdicts,
an AI coach chat grounded in the report, a deterministic "Fix Rack" that turns
committed fixes into an audible mastering chain, and a Listen page that plays
the track through a real-time Web Audio DSP rack (EQ, compressor, saturation,
M/S width, pitch). An anonymous funnel offers the first analysis with no
account; registration claims it. Tiers: free / pro / credits (Stripe). Single-user
tool — no sharing, no profiles, no rooms; see `PRPs/solo-fork-strip-social.md`.

## Repository structure

Monorepo, five active parts + two legacy parts (see `source-tree-analysis.md`):

| Part | Root | Type | Role |
|---|---|---|---|
| frontend-v2 | `components/frontend-spectr-v2` | web SPA | All user-facing UI |
| bff | `components/bff` | backend | Auth, REST API, uploads, job dispatch, billing |
| worker | `components/worker` | backend | Analysis pipeline, AI verdicts/coach, maintenance |
| analysis | `components/analysis` | library | `audio_analysis` measurement pipeline |
| shared | `components/shared` | library | SQLAlchemy mirror of the EF schema + verdict scoring |
| api (legacy) | `components/api` | backend | FastAPI v1, being folded into bff/worker |
| frontend-spectr (legacy) | `components/frontend-spectr` | web | v1 SPA, superseded |

## Technology summary

| Category | Technology |
|---|---|
| Frontend | React 19, Vite 6, TypeScript strict, TanStack Router + Query, CSS Modules, WaveSurfer, Recharts, Sonner |
| Backend API | ASP.NET Core .NET 10 minimal APIs, EF Core 10 + Npgsql, JWT bearer + refresh cookie |
| Jobs | Python 3.11 dramatiq over Redis (4 queues: coach, analysis-paid, analysis-free, maintenance) |
| Audio analysis | librosa, pyloudnorm, Demucs/torch (numpy<2.0 pin), allin1 in Docker for structure |
| AI | Anthropic Claude — `claude` CLI in dev (subscription), SDK/API in prod; LLM_FAKE canned mode |
| Data | PostgreSQL 16 (EF Core canonical schema), Redis 7 |
| Storage | IFileStorage: local disk (dev) / R2-S3 presigned (prod), MinIO optional locally |
| Payments/Email | Stripe (webhook-idempotent), Resend |
| Prod infra | Docker compose (`infra/compose.prod.yml`): caddy, bff, worker-paid, worker-free, prometheus/grafana |

## Architecture type

Multi-part service architecture: SPA → BFF (single API gateway) → Postgres +
Redis-queued Python worker. No direct frontend↔worker path; everything user
facing flows through the BFF. Details per part in `architecture-*.md`;
cross-part contracts in `integration-architecture.md`.
