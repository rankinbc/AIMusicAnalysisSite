# Source Tree Analysis

Annotated repository map for AI-assisted development. Generated by the BMAD
document-project workflow (deep scan, 2026-07-22). Part docs: see `index.md`.

## Repository type

Monorepo, multi-part. Five active parts (frontend-v2, bff, worker, analysis,
shared) plus two legacy parts being phased out (api, frontend-spectr) and
project-level infra folders. All parts share one Postgres 16 and one Redis 7
(Docker in dev).

## Part interfaces (summary)

frontend-v2 → bff: REST `/api/*` + SSE (Vite proxy in dev). bff → Redis: dramatiq
message enqueue (HASH+LIST wire format). worker ← Redis: consumes 4 queues. bff
and worker → the same Postgres (EF Core / SQLAlchemy sync). worker → Docker
`allin1:latest` per-track for structure detection; → Anthropic via `claude` CLI
(dev) or SDK (prod). Details: `integration-architecture.md`.

## Critical folders for common tasks

- New endpoint: `components/bff/src/Spectr.Bff/Endpoints/` (+ DTOs, + EF entity in Spectr.Data if schema changes — EF migration required)
- New UI surface: `components/frontend-spectr-v2/src/features/<feature>/` + route under `src/routes/`
- New background job: `components/worker/app/` actor + queue choice (never `default`)
- Analysis change: `components/analysis/src/audio_analysis/` (golden snapshots guard `run_pipeline` output)
- Schema change: EF entity + migration FIRST (canonical), then mirror in `components/shared/aimusic_shared/models.py`
